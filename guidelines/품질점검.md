# 품질점검 체크리스트

cycle 진행 중 **finding 2개를 처리할 때마다**(또는 주요 변경 후) 이 체크리스트로 전반적 건전성을 점검하고, 문제가 있으면 개선 goal을 생성해 처리한다.

## 1. 메타시스템 / FCG 정합성
- [ ] `bash scripts/diagnose.sh` — active-goal·열린 finding·blocker 상태가 의도와 일치하는가
- [ ] `bash scripts/completion-check.sh` — 전체 게이트 체인이 green인가 (실패 시 active-goal로 기록됨)
- [ ] `bash scripts/check-gate-rigor.sh` (또는 게이트 내장 self-check) — universal claim ↔ enumerating gate 일치
- [ ] 게이트가 convention police로 변질되지 않았는가 (테스트/타입체커가 잡을 것을 grep으로 하드코딩하지 않았는지)

## 2. Lint / 타입 / 빌드 (`_meta` goal 영역)
- [ ] linter 통과
- [ ] 타입체커 통과
- [ ] 빌드 통과
- [ ] 미사용 코드/import 정리

## 3. 테스트 코드
- [ ] 새/변경 동작에 대응하는 테스트가 RED→GREEN으로 추가됐는가
- [ ] 테스트가 구현 detail이 아니라 동작/계약을 검증하는가
- [ ] 자세한 점검 지침은 `prompts/check-test-codes/` 참고

## 4. findings 위생
- [ ] 닫은 finding은 코드 대조 후 `resolved: true` + 증거(file:line/테스트명) 인용
- [ ] 부분 종결은 `status_notes`에 남은 항목 명시
- [ ] 새 부채는 즉시 `docs/findings/`에 큐잉(범위 밖이면 고치지 말고 기록)

> 점검 중 발견한 개선사항이 gate 검증 가능한 invariant면 goal로 promote, 아니면 finding으로 큐잉한다.
