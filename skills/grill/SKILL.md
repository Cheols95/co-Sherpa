<what-to-do>

"기획이 끝났나?"를 느낌이 아니라 **열린 체크박스의 수**로 바꾸는 grilling 대화다. 한 기능의 결정표면을
`docs/grill/checklist.md`에 정산하고, 각 슬롯을 사용자와 함께 닫은 뒤, 남은 게 없으면
**"기능 X 닫힘 — /freeze ready"**를 선언한다.

규칙의 권위는 `docs/grill/AGENTS.md`(4렌즈·grounds-gate·exit bar·2방향 감사) — **grilling 시작 전 반드시
읽는다**. 체크리스트 형식·닫힘 상태·입장 규칙은 `docs/grill/README.md`에 있다. 이 스킬은 그것을 *운영*하는 법이다 — 규칙을 사용자에게
낭독하지 말고 시퀀스를 끌고 가라.

루프:
1. **체크리스트 생성/갱신** — 4렌즈 스캔으로 슬롯을 열거한다(자유연상 아님).
2. **슬롯을 하나씩 닫는다** — 각 결정을 닫힘 근거와 함께 그 자리에서 기록.
3. **닫힘 선언** — 미표기 `[ ]`와 미정산 `[>]`가 0이 되면.

질문은 한 번에 하나씩, 답을 기다린다. 코드베이스에서 답할 수 있는 질문은 묻지 말고 탐색한다.

</what-to-do>

## 결정표면 정산 (체크리스트)

형식, 4종 닫힘 상태 `[x]/[~]/[>]/[-]`, 입장 규칙, 닫힘 판정은 모두 `docs/grill/README.md`에 있다 —
그걸 따른다. 운영 노트:

- **자유연상이 아니라 스캔으로 열거한다.** 먼저 **엔티티 매니페스트**(기능이 건드리는 모든 엔티티·행위자·
  상태보유자·외부 시스템)를 적는다. 그다음 각 엔티티와 *충돌쌍*에 4렌즈를 적용해 의무 슬롯을 끌어낸다.
  이름 붙이지 않은 것은 훑지 못한다.
- **입장 = grounds-gate.** 슬롯은 site·**왜 기존 자료로 정산 안 되는지(능동 논증)**·오추측 consequence
  3요소를 못 대면 소음이니 버린다 — ground②가 종료 엔진. 전수 형식·빈칸 금지(빈칸은 "닫힘"이 아니며
  /freeze residual-enumeration 감사 대상). 정책 전문은 `docs/grill/AGENTS.md`, 3요소·4종 표는
  `docs/grill/README.md` 참조.
- **결정이 날 때 근거를 함께 적는다**(몰아서 적지 말 것). hard-to-reverse면 ADR 번호, 가벼우면
  rationale 한 줄(ADR 강제 안 함). 실험이면 `[>]`에 어느 프로토타입이 정산하는지 명명. 배제면 `[-]`에
  배제 근거.

## 4렌즈 질문 카탈로그 (스캔을 기계적으로)

- **STRUCTURAL** — 카디널리티(*one X = one/many Y?*), 정체성, 구성, 관계. 조용한 카디널리티 추측을
  통과시킨 바로 그 렌즈 — 절대 건너뛰지 말 것.
- **BEHAVIORAL** — 수명주기(생성 → 변경 → 종료), 동시성(공유 상태를 두고 경쟁하는 행위자 → 원자성 /
  tie-break / 순서), 정책, 엣지 처분. **충돌쌍을 훑는다**: "취소 가능" + "결제 보유" → "취소 시 결제는?".
- **TECHNICAL** — 저장, 인터페이스 / 전달 형태, 일관성 모델.
- **CONTRACT** — 상태/enum 값 *집합*, 유일성/정체성 규칙, 출력 키, 두 개념이 한 필드로 뭉뚱그려진 것.

렌즈는 가속기지 전수 목록이 아니다 — load-bearing 슬롯이 어디에도 안 맞으면 새 렌즈를 명명하라(억지로
끼우지 말 것). 종료 floor("조용한 추측을 남긴 슬롯 0")는 렌즈와 무관하다.

## 어떻게 물을까 — EXTRACT vs PRESENT (비개발자에게 최고 가치)

**지식이 누구에게 있느냐**로 방법을 고른다:

- **도메인 / 행위 → EXTRACT.** 사용자가 안다; 끌어낸다("X일 때 어떻게 되어야 하나?"), 끝까지 캐고,
  발명하지 않는다. 도메인 질문을 선택지로 줄 때는 **항상 명시적 open option**("이 중 없음 — 내 생각은
  따로")을 넣는다 — 당신의 선택지는 발판이지 사용자 모델의 경계가 아니다.
- **기술 → PRESENT.** 당신이 안다; 사용자의 일반론을(추출한 도메인에 근거해) 구체적 옵션 +
  트레이드오프로 옮기되 **추천을 먼저** 제시한다; 사용자는 고르기만. load-bearing 기술 기본값은 절대
  조용히 두지 말고 한 박자에 제시한다. PRESENT는 EXTRACT에 의존한다 — 옵션이 봉사할 도메인을 먼저
  이해하라.
- **진짜로 사소한 것**(다운스트림 무게 없음, 사용자 선호 없음) → 그냥 정한다; 그건 추측이 아니다.

모든 질문은 추천/기본값과 함께 던진다 — 구체적 제안이 빈 칸보다 답하기 빠르다. 도움이 되면 관련 질문 몇
개를 묶는다(플랫폼 한계: 구조화 프롬프트당 옵션 4 / 질문 4; 거부되면 평문으로 다시 묻는다).

**test seam도 여기서 정산한다.** `to-prd`가 "어디서 테스트하나"를 묻지만 `/freeze`는 sealed로 돈다
(번들 중간 질문 없음) — 그러니 seam은 grilling 중에 닫는 체크리스트 슬롯(기술/계약 렌즈)이지, freeze에서
다시 떠오르는 질문이 아니다.

## 다듬기 (기존 grill에서 유지)

- **용어집 도전.** `CONTEXT.md`와 충돌하는 용어는 즉시 짚는다("용어집은 '취소'를 X로 정의하는데, 지금은
  Y를 말하는 듯 — 어느 쪽?").
- **모호한 말 날카롭게.** 과적재된 용어 → 정확한 정본 용어를 제안한다("'계정' — Customer? User? 둘은
  다르다").
- **시나리오로 압박.** 경계의 정밀함을 강제하는 구체적 엣지 시나리오를 지어낸다.
- **코드와 교차 확인.** 사용자가 작동 방식을 말하면 코드가 동의하는지 확인하고 모순을 짚는다("코드는 Order
  전체를 취소하는데, 부분 취소가 가능하다고 했다 — 어느 쪽?").
- **`CONTEXT.md` 인라인 갱신** — 용어가 정해질 때마다(용어집만, 구현 디테일 금지; ./CONTEXT-FORMAT.md
  참조). 첫 용어가 정해질 때 lazily 생성한다.

## ADR — 아껴서

ADR은 **셋 다** 참일 때만 제안한다: 되돌리기 어렵다 · 맥락 없이는 의외다 · 진짜 트레이드오프의 결과다.
아니면 닫힘 근거는 ADR이 아니라 rationale 한 줄이다. **결정 하나 = ADR 파일 하나**(./ADR-FORMAT.md);
대체(supersede)는 파일 단위로 한다.

## 마무리

기능의 체크리스트에 `[ ]`도 미정산 `[>]`도 없으면 **"기능 X 닫힘 — /freeze ready"**를 선언한다.
동결 후에는 새 기획거리 → `docs/findings/`, 동결 결정의 근본 오류 → 사용자 승인 후 grilling 재오픈
(`docs/grill/AGENTS.md`).
